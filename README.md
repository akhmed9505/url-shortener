# Shortener

Shortener — сервис сокращения URL на Go с хранением ссылок и событий переходов в PostgreSQL. Приложение предоставляет HTTP API для создания ссылок, перенаправления и получения публичной аналитики. Встроенный веб-интерфейс позволяет проверять эти операции через браузер.

## Возможности

- Создание ссылки со случайным восьмисимвольным Base62-кодом или своим кодом длиной 3–32 символа.
- Редирект с регистрацией времени перехода и User-Agent.
- Сводка переходов за всё время и выбранный период, статистика по дням, месяцам и User-Agent.
- История переходов с курсорной пагинацией.
- Кеширование ссылок в Redis, ограничение частоты создания ссылок и запросов аналитики.
- Liveness, readiness, структурированные HTTP-логи и graceful shutdown.

Аналитика публичная, аккаунтов и авторизации нет. IP посетителей не сохраняются. User-Agent сохраняется в пределах 1024 байт и может содержать идентифицирующие сведения.

## Запуск

Для запуска нужны Make, Docker Engine и Docker Compose v2.24+.

```sh
git clone https://github.com/akhmed9505/url-shortener.git
cd url-shortener
cp .env.example .env
# Заполните PGUSER, PGPASSWORD и PGDATABASE в .env.
make docker-up
```

Веб-интерфейс доступен на `http://localhost:8080`. Миграции применяются автоматически. Порты публикуются на `127.0.0.1`, данные PostgreSQL сохраняются в именованном томе `postgres_data`.

Команды Make:

- `docker-up` — сборка и запуск стека с ожиданием готовности.
- `docker-down` — остановка стека с сохранением данных.
- `run` — локальный запуск Go-приложения с настройками из `.env`.
- `build` — сборка в `bin/shortener`.
- `test` — модульные тесты.
- `test-integration` — интеграционные тесты с отдельными PostgreSQL и Redis.
- `check` — проверка форматирования, тесты, проверка гонок, `go vet` и сборка.

## Конфигурация

Параметры приведены в [.env.example](.env.example). Перед запуском создайте `.env` и заполните `PGUSER`, `PGPASSWORD` и `PGDATABASE`. Compose требует этот файл и сообщает об отсутствующих параметрах.

- `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `PGSSLMODE` обязательны для Go-приложения. В Compose адрес БД заменяется на `postgres:5432`. Приложение, PostgreSQL и Goose используют одни учётные данные.
- `APP_PORT` задаёт порт приложения на хосте, внутри контейнера используется `8080`. Для локального запуска адрес задаётся через `HTTP_ADDR`.
- `PUBLIC_BASE_URL` задаёт HTTP/HTTPS-адрес коротких ссылок без пути, логина, пароля, параметров и фрагмента. Если он указан в `.env`, обновляйте его вместе с `APP_PORT`.
- `POSTGRES_PORT` и `REDIS_PORT` задают опубликованные порты зависимостей. Для локального Go-приложения согласуйте с ними `PGPORT` и `REDIS_ADDR`. В Compose Redis доступен по `redis:6379`.

Для существующего тома используйте действующие учётные данные. Изменение `.env` не обновляет пароль существующей роли PostgreSQL.

Пример запуска на других портах:

```sh
APP_PORT=8081 PUBLIC_BASE_URL=http://localhost:8081 \
POSTGRES_PORT=55433 REDIS_PORT=56380 make docker-up
```

## API

Примеры используют стандартный порт. Пользовательский код `demo-link` можно создать один раз, повторный запрос вернёт конфликт.

### Создание ссылки

```sh
curl -i http://localhost:8080/shorten \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.org/page","alias":"demo-link"}'
```

Ответ `201 Created`, заголовок `Location` содержит короткую ссылку. JSON содержит `code`, `url`, `short_url`, `created_at`.

Без `alias` код генерируется автоматически. Свой код — 3–32 латинские буквы, цифры, `_` или `-`. Допустим абсолютный HTTP/HTTPS URL до 2048 байт без учётных данных, пробелов, управляющих символов и обратных слешей. JSON — до 4 КиБ, без неизвестных и повторяющихся полей.

### Редирект

```sh
curl -i http://localhost:8080/s/demo-link
```

Ответ `302 Found`, `Location` с исходным URL и `Cache-Control: no-store`. HEAD возвращает `405` и не регистрирует переход.

### Сводная аналитика

```sh
curl http://localhost:8080/analytics/demo-link
curl 'http://localhost:8080/analytics/demo-link?from=2026-11-01&to=2026-12-01'
```

`from` и `to` передаются парой в формате `YYYY-MM-DD`. Интервал `[from, to)` в UTC, максимум 366 дней. По умолчанию берутся текущий день и 29 предыдущих дней.

Основные поля ответа:

- `code`, `url`, `from`, `to` — ссылка и период.
- `total_visits`, `period_visits` — количество переходов за всё время и за период.
- `daily`, `monthly` — количество переходов по дням и месяцам, включая нулевые значения.
- `user_agents` — 20 самых частых User-Agent, `other_user_agents_visits` — сумма остальных.

### История переходов

```sh
curl 'http://localhost:8080/analytics/demo-link/visits?from=2026-11-01&to=2026-12-01&limit=20'
```

Поля ответа:

- `code`, `from`, `to` — код ссылки и период.
- `items` — переходы со строковым `id`, временем `visited_at` и `user_agent`.
- `next_cursor` — курсор следующей страницы или `null` в конце списка.

`limit` по умолчанию 20, максимум 100. Сортировка — `(visited_at DESC, id DESC)`.

Для следующей страницы подставьте полученный `next_cursor`, сохранив код и период:

```sh
curl --get http://localhost:8080/analytics/demo-link/visits \
  --data-urlencode 'from=2026-11-01' \
  --data-urlencode 'to=2026-12-01' \
  --data-urlencode 'limit=20' \
  --data-urlencode 'cursor=CURSOR_FROM_PREVIOUS_RESPONSE'
```

При передаче курсора обе даты обязательны. Некорректный курсор возвращает `400 invalid_cursor`.

### Проверки состояния

```sh
curl http://localhost:8080/health/live
curl http://localhost:8080/health/ready
```

`/health/live` проверяет работоспособность процесса. `/health/ready` за 1 секунду проверяет PostgreSQL и актуальность схемы, возвращая `200` или `503`. Redis на результат не влияет. Успешный ответ — `{"status":"ok"}`.

### Ошибки и ограничения

Единый формат ошибки:

```json
{
  "error": {"code": "alias_taken", "message": "Alias is already in use", "field": "alias"},
  "request_id": "request identifier"
}
```

`field` указан при ошибке конкретного поля. Основные статусы:

- `400` — ошибка валидации, `404` — ссылка не найдена, `409` — код занят.
- `413` — превышен размер тела, `415` — неверный Content-Type.
- `429` — превышен лимит, `500` — внутренняя ошибка.
- `503` — хранилище недоступно, `504` — таймаут операции.

Ограничения на один IP:

- Создание — 10 запросов/мин, допустимый всплеск 5.
- Оба маршрута аналитики совместно — 60 запросов/мин, допустимый всплеск 10.
- Для редиректов лимит не установлен.

Ответ `429` содержит `Retry-After`. IP определяется по `RemoteAddr`, заголовки прокси игнорируются.

## Тестирование

Нужны Go 1.27.3 и компилятор C для проверки гонок данных. Интеграционные тесты дополнительно используют Docker Compose.

```sh
make test
make check
make test-integration
```

`test-integration` запускает PostgreSQL и Redis через `docker-compose.test.yml` в проекте `shortener-test` на портах 55432/56379. Используются тестовые реквизиты, локальный `.env` не загружается. Контейнеры удаляются после завершения. Каждый тест создаёт собственную БД и удаляет её, требуется право CREATEDB. Адреса можно переопределить через `TEST_POSTGRES_DSN` и `TEST_REDIS_ADDR`.

## Кеширование и аналитика

PostgreSQL используется как основное хранилище данных. Redis кеширует ссылки на 1 час по умолчанию. При ошибке или отсутствии записи в кеше выполняется запрос в PostgreSQL. Найденная в кеше ссылка доступна для перенаправления даже при недоступной БД.

Переходы записываются синхронно с отдельным таймаутом. Ошибка записи не препятствует перенаправлению, поэтому статистика может быть неполной. Время хранится в UTC. Сводка формируется в одной транзакции REPEATABLE READ.
